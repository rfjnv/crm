# Дашборд: почему читается как старое и каким должен быть

Техническое задание на пилот 0. Написано по разбору скриншотов нового (modern) и классического дашборда
шестью независимыми линзами (композиция, материал, типографика, цвет, данные, ДНК каркаса), карте кода и
проверке рецензентом. Все ссылки `файл:строка` — на состояние ветки на 13.10.2026; пути относительно
`frontend/src/`. Правила отсюда наследуют примитивы §5 брифа и все остальные страницы.

---

## 1. Диагноз в пяти признаках

Догадка пользователя верна буквально, а не психологически. Под приветствием в новом дизайне нет ни одной
строки собственной разметки: `pages/DashboardPage.tsx:469–1266` рендерит один JSX для обоих режимов.
В разметке режим ветвится только у приветствия (:399) и среза остатков (:379); ещё семь точечных веток
`modern` живут в пропсах — цвета товара дня (:168), график (:823, :826–830, :835, :848), список статусов
(:877). Сайдбар и шапка написаны заново на своём словаре (`sider-*`, `hdr-*`, Phosphor, hover-glider), а
контент — это классика, перекрашенная правилами `theme/glass.css:283–398, 1053–1136` с `!important`.
Глаз читает структуру раньше фактуры, и структура говорит «старое». Пять признаков:

1. **Силуэт страницы совпадает один в один.** Четыре KPI-коробки `Col lg=6` (:536–634) → таблица
   пропущенных → две полоски целей (`marginTop 16`, :692, :744) → ВЭД с тремя плитками → график `lg=14` +
   статусы `lg=10` (:802, :869) → «Товар дня» во всю ширину → три топа `md=8` → таблица остатков. Те же
   гуттеры `[16,16]` (:389). Поменялись радиус (10 → 24, `glass.css:289`) и прозрачность. Структура — нет.
2. **Каждый блок — та же «коробка»: заливка + 1px рамка + заголовок 14/600 + синяя ссылка в углу.** На
   первом экране 21 замкнутая светлая обводка (окно + 8 карточек + 3 плитки ВЭД + 9 пилюль) против одной у
   сайдбара и нуля у шапки. Рамка рождается в `theme/theme-variables.css:42–46` (глобальный `!important`
   классики); `glass.css:285–287` перекрашивает три грани из четырёх.
3. **Текст набран инлайнами старой страницы.** Заголовки `Typography.Text strong style={{fontSize:14}}`
   (:808, :875, :928, :1150, :1205), подписи 13 (:547…), мета 12 (:729), ранги 11/700 (:996). Каркас набран
   eyebrow 11/600/uppercase/.06em (`glass.css:1003–1010`) и строками 14 (`:606–620`). Самое крупное число
   страницы (KPI) имеет вес 500, самый мелкий текст (капс таблиц 12px) — 600: иерархия перевёрнута.
4. **Палитра antd на тех же местах.** Зелёная полоса `#52c41a` и пилюли `success/gold` в «Сделках по
   статусам» (:883–887, `DealStatusTag`), красные теги даты и «Блок» ×3, красный бейдж «72», красные нули
   остатков, корона `#faad14`, синие `<Link>` в углах. На одном экране три красных, четыре зелёных, пять
   синих; в каркасе — белый + один акцент (аватар) + один `#ef4444` у счётчика.
5. **Данные показаны «как пришли».** Первое, что видно утром: «0 so'm —», «0 —», «0 % · 0 so'm /
   100 000 000 so'm», «Нет продаж за выбранный день» на панели 1 700×100. Факт «сегодня продаж нет» повторён
   четырежды, а `revenueYesterday`, `revenueMonth`, `debts.totals.clientCount`, `finance.overdueDebts`,
   `topDebtors`, `period.label` уже загружены и не показаны нигде.

Вывод: дашборд не докрашивать, а пересобрать из словаря сайдбара и шапки. Это правильная страница для
эталона: здесь боль, и здесь рождается язык (материал, шрифт, цвет, числа), который потом потребляют все
страницы.

## 2. ДНК, которой должен следовать контент

Взято из `glass.css`, `components/Layout.tsx`, `components/ModernHeaderBar.tsx`,
`components/DashboardGreeting.tsx`. У контента нет права на другие числа.

1. Один материал: в тёмной теме белая альфа без оттенка (панель .07, кнопка .10, hover .18, glider .09,
   активный пункт .16), в светлой — тёмная альфа `rgba(28,26,23,…)` по таблице §3. Рамка только у плавающего
   слоя (.22 окно, .18 сепараторы).
2. Радиусы растут с размером поверхности: окно 40 → панель меню и профиля 20 → **группа внутри окна 16** →
   строка 12 → пункт/кнопка 10 → пилюля 999. Значения 24 в словаре нет.
3. Высоты: 34 (подпункт, кнопка в панели) / 36 (пункт меню) / 40 (кнопка шапки, пилюля периода, аватар) /
   44 (строка панели) / 72 (шапка).
4. Отступы: панель 8 со всех сторон, строка `0 10px`, пилюля `0 14px`, контент окна `4px 28px 28px`,
   зазор между кнопками 10.
5. Активное состояние — только заливка .16 + rim `inset 0 1px 0 rgba(255,255,255,.2)` и белый текст;
   без обводки, без фирменного синего.
6. Hover — не фон у каждого элемента, а одна плашка .09, которая переезжает за курсором за .3s
   `cubic-bezier(.32,.72,0,1)`; ничто не подпрыгивает (`translateY` внутри окна запрещён).
7. Движение: .15s кнопки, .22s появление панели, .3–.34s glider; всё под `prefers-reduced-motion`.
8. Типографика: Inter; приветствие 32/600/−0.02em; строка панели 14/400; имя 15/600; eyebrow
   11/600/uppercase/.06em; числа `tabular-nums`.
9. Иконки — только Phosphor regular 18, одна на строку в колонке 20px с opacity .8; caret 14 с opacity .7
   ПОСЛЕ текста.
10. Цвет = смысл: оттенок только у аватара, красного счётчика `#ef4444` и «Выход»; текст `#fff`, пункты
    `rgba(241,245,249,.75)`.
11. Тень только у плавающих слоёв (меню, окно, панель профиля); у всего внутри окна — rim или ничего.
12. Разделители — 1px `rgba(255,255,255,.18)` с `padding 4px 0` или `margin 8px 16px`; никаких рамок вокруг
    строк и сеток ячеек.
13. Глубина вложенности ≤ 2: поверхность → строка; содержимое строки — иконка 18 + подпись + контрол справа;
    «коробка в коробке» запрещена.
14. Один сильный акцент на экран — инвертированная пилюля выбранного состояния; больше ни один элемент не
    бывает сплошным.

## 3. Система материала

Три уровня, один словарь токенов в `glass.css` (переменные dark :20–38, light :40–59). Те же токены
обязаны получить сплошные подмены в фолбэках `:443–456` (`--fill-1: var(--card-bg)`,
`--fill-2/--fill-3: color-mix(in srgb, var(--text-primary) 8% / 14%, var(--card-bg))`, `--c-*-bg` —
сплошные аналоги, `--win-blur: none`).

| Уровень | Что это | Dark | Light | Радиус | Тень/rim |
|---|---|---|---|---|---|
| **A — окно** | `.app-shell` окно, сайдбар, `hdr-panel`, поповеры, дроверы | `--win-bg: rgba(44,48,52,.52)` (замер, Q7), `--win-blur: blur(48px) saturate(115%)`, рамка `.22` | `rgba(255,255,255,.50)` + вуаль `rgba(255,255,255,.15)` на фото в `body::before` (Q7), рамка `.45` | 40 (≤767: 28) | `--win-shadow` + `--win-rim` |
| **B — группа** (`Section`) | панель внутри окна | `--fill-1: rgba(255,255,255,.05)`, hover `.08`, **без рамки**, `box-shadow: none` | `rgba(255,255,255,.18)`, hover `.24` | 16 | нет (допустим `inset 0 1px 0 rgba(255,255,255,.06)`) |
| **C — элемент** | строка списка, рельс прогресса, пилюля, чип, ячейка | `--fill-2: rgba(255,255,255,.10)` (рельс, hover строки, неактивная пилюля); `--fill-3: rgba(255,255,255,.16)` + rim `.2` (активное) | `--fill-2: rgba(28,26,23,.06)`; активное `--fill-3: rgba(28,26,23,.16)` + rim `inset 0 1px 0 rgba(255,255,255,.5)` | строка 10, пилюля 999, рельс 999 | нет |

Правила применения:

- Запрет повтора токена на соседних уровнях: ребёнок уровня B не может быть `--fill-1`. Сейчас `--panel-bg`
  стоит и на карточке (:284), и на плитках ВЭД (:1077), рельсах (:1065, :1129), кружках рангов (:1119),
  hover строк (:396) — это и есть «стекло в стекле».
- Обводка — признак только уровня A. `.ant-tag`, `.ant-segmented-item`, кружки рангов, плитки — без `border`.
- Hover уровня B — шаг заливки `.05 → .08`, `transform: none`.
- Радиусы контента: `Section` 16 (как выпадающие панели `glass.css:1242`), строка 10 (как пункт меню :148 и
  кнопки :1174), пилюля/рельс 999. 16 вместо 20 панели профиля — потому что `Section` лежит внутри окна с
  padding 28 и не плавает.
- Ритм: 24px между панелями внутри зоны, 40px между зонами; eyebrow зоны стоит над группой, а не внутри
  каждой карточки.
- Одно сплошное пятно на экран. Тёмная тема: активная пилюля — `--fill-3` + rim, как
  `.ant-menu-item-selected` (:151–155), кремовый `--chip-active-bg` (:32) не используется. Светлая тема:
  если замер контраста текста на `--fill-3` light поверх дефолтного светлого фото < 4.5:1 — оставить
  сплошную тёмную пилюлю из `:53–54` как единственное пятно светлой темы.
- Глобальное правило карточек `glass.css:283–296` (рамка, радиус 24, подъём на hover) на других страницах
  **не трогаем** до их миграции — дашборд в modern карточек `.ant-card` не использует вовсе (см. DoD).
- Светлая тема: фото под окном осветляется вуалью `rgba(255,255,255,.15)` в `body::before` (аналог
  `--scene-dim` тёмной темы), поэтому окно остаётся тонким (.50), а подписи `--c-text-2` держат ≥ 4,5:1 и на
  голом окне, и внутри `Section` (замер, Q7).

Куда переходит текущее:

| Сейчас | Становится |
|---|---|
| `.ant-card` на дашборде (`glass.css:283–296`, инлайн `card` :383–387) | `Section` уровня B: `--fill-1`, без рамки, радиус 16, padding 20 |
| `.dashboard-metric-card` (4 коробки) | герой (B) + панель-список KPI (B) со строками 44px (C); `container-type`/`clamp` (:304–315) не нужны в modern |
| `.ved-stat` (плитки `:1075–1095`) | строка счётчиков в eyebrow секции, без фона; `box-shadow`-свечение точек удаляется |
| две `Card` целей (:688, :740) | дневная цель — строка в герое, месячная — бар 280px в заголовке графика; рельс `--fill-2` 6px/999 |
| `.dash-top-rank` кружки (:1117–1126) | цифра 13/600 tabular в колонке 20px; #1 — `--fill-3` диск 22px |
| antd `Table` в карточке (пропущенные, остатки) | список строк 44px уровня C внутри секции панели внимания; разделители `rgba(255,255,255,.08)`, hover `--fill-2`; капс-шапка остаётся только у будущего `DataTable` |
| `.ant-segmented` (:361–386) на дашборде | неактивный сегмент — без фона/рамки, активный — `--fill-3` + rim |

## 4. Типографика и числа

Шкала из шести ступеней — классы `ui-type-*` или примитивы `Eyebrow`, `StatTile`, `Money`. Все инлайновые
`fontSize`/`fontWeight` из `DashboardPage.tsx` и `VedEventsQuickAccessCard.tsx` в modern-ветке не
используются. Display 32 — только `.dash-greeting`; `h4.ant-typography` остальных страниц остаётся 28
(`glass.css:1160–1165` не трогать) до пилота `PageHeader`.

| Ступень | Размер/вес/трекинг/интерлиньяж | Назначение |
|---|---|---|
| Display | 32/600/−0.02em/1.15 (≤768: 24) | приветствие |
| Hero | 40/600/−0.02em/1.05, tabular | одно число на страницу — «Выручка сегодня» (без доступа к выручке — «Активные сделки») |
| Stat | 20/600/−0.01em/1.2, tabular | числа в KPI-списке, счётчики в eyebrow («Остатки · 72») |
| Body | 14/400/0/1.45 (14/500 — пилюли, действия) | строки списков, названия, ячейки |
| Caption | 13/400/0/1.4, `--c-text-2` | подписи, база сравнения «вчера 12,4 млн», мета целей, пустые состояния |
| Eyebrow | 11/600/+0.06em/uppercase, `--c-text-3` | заголовки зон и секций |

Вес числа всегда ≥ веса соседней подписи. Веса 700 и размеры 36/18/12/11-с-другим-трекингом исчезают.

**Деньги.** Новые хелперы в `utils/currency.ts` рядом с `formatUZS` (существующие `formatUZS`,
`formatFullNumber`, `formatShortNumber` **не меняются** — их используют классика и другие страницы):

- `formatMoneyCompact(value): { text: string; unit: 'млн' | 'млрд' | null; full: string; hidden: boolean }`;
  при `null/undefined` или `isMoneyHidden()` → `{ text: HIDDEN_MONEY, unit: null, full: HIDDEN_MONEY, hidden: true }`.
  Пороги: ≥ 1 млрд → «1,9 млрд»; ≥ 100 млн → «681 млн»; ≥ 1 млн → «12,4 млн»; меньше — полная сумма с
  пробелами. Десятичный разделитель — запятая (`toLocaleString('ru-RU', { maximumFractionDigits: 1 })`).
- `formatPercent(value, digits: 0 | 1)` — с запятой.
- `formatCount` переносится из `DashboardPage.tsx:79–83` в `utils/currency.ts` (экспорт без изменения
  поведения), `DashboardPage` импортирует его оттуда.
- Hero и Stat — компактно; `unit` отдельным span Caption; полная сумма в `title` и в тултипе.
- Цели: «681 млн / 2,5 млрд so'm» — единица один раз.
- Списки — полная сумма с пробелами, `so'm` — span Caption; выравнивание вправо, фиксированная колонка.
- `html[data-design='modern'] .dashboard-page { font-variant-numeric: tabular-nums }`; счётчики через
  `formatCount` («13 572», не «13572»).
- Проценты: в барах — целое («27 %»), в дельтах — одна десятая с запятой («+12,5 %»).
- Даты везде `DD.MM` (ось X `dayjs(v).format('DD.MM')` вместо `v.slice(5)` :302, :313), полная дата в `title`;
  modern-график передаёт в `labelFormatter` оси Y `formatMoneyCompact(v).text`.

**Пустые значения.**

- «—» только для `null`/неприменимого (ячейка, пара «подпись — значение»). Ноль — цифра «0» с opacity .45,
  не прочерк (`calls/MissedCallsWidget.tsx:62`).
- `DeltaBadge` остаётся как есть для классики; в modern дельта рендерится `StatTile` с пропом
  `delta: number | null` (`null` → ничего, строка не резервируется). Правила `DashboardPage.css:6–9` и
  `.dashboard-card-delta-placeholder` остаются классике.
- Вместо дельты при нулевом текущем периоде — Caption «вчера {revenueYesterday} · месяц {revenueMonth}».
- Блок без данных — одна строка Caption с датой и действием («Нет продаж за 13.10 · Показать вчера»), без
  `min-height`; полностью нулевая секция — одна строка-резюме, не таблица и не плитки.
- В одной строке «0» и «—» не смешиваются; цвет у нуля всегда нейтральный.

## 5. Цвет

Семантические токены в `glass.css` (dark :20–38, light :40–59). Единый источник значений —
`theme/glassPalette.ts` (TS-зеркало для G2-графиков и antd-токенов: они не читают `var()`); `glass.css`
дублирует значения с комментарием `sync glassPalette.ts`. `tokens.ts:90` и `:100` (`--text-secondary`),
`:203` (`Table.headerColor`) получают те же литералы, что `--c-text-2`.

| Токен | Dark | Light | Где |
|---|---|---|---|
| `--c-text-1` | `#ffffff` | `#1c1a17` | числа, названия, активное |
| `--c-text-2` | `rgba(255,255,255,.82)` | `rgba(28,26,23,.80)` | подписи, мета, оси, действия секций |
| `--c-text-3` | `rgba(255,255,255,.55)` | `rgba(28,26,23,.50)` | eyebrow, плейсхолдеры, прочерки |
| `--c-accent-fg` / `--c-accent-fill` | `#93c5fd` / `#4f8cff` | `#1d4ed8` / `#2563eb` | ссылки внутри данных, линия и заливка графика, бар целей |
| `--c-pos-fg` / `--c-pos-bg` | `#86efac` / `rgba(34,197,94,.16)` | `#15803d` / `rgba(22,163,74,.14)` | статус CLOSED, дельта > 0, цель ≥ 100 % |
| `--c-warn-fg` / `--c-warn-bg` | `#fcd34d` / `rgba(245,158,11,.16)` | `#b45309` / `rgba(217,119,6,.12)` | ожидающие статусы, остаток ниже минимума, отставание от темпа |
| `--c-neg-fg` / `--c-neg-bg` | `#fca5a5` / `rgba(239,68,68,.16)` | `#b91c1c` / `rgba(220,38,38,.12)` | CANCELED/REJECTED, дельта < 0, нулевой остаток, «Блок», просрочка |
| `--c-alert` | `#ef4444` | `#dc2626` | только счётчики «нужно действие»: колокольчик, «не перезвонили», просроченные долги |

Правило: нейтраль по умолчанию; акцент — выбранное и ссылки в данных; семантика — только статус, риск,
дельта; при нуле цвета нет. Единственный разрешённый градиент — бар цели месяца `#60a5fa → #4f8cff`.

Не используется в modern-ветке дашборда: карта hex antd v5 (`DashboardPage.tsx:883–887`), инлайн
`strokeColor` (:707, :724, :759, :776), `PRODUCT_DAY_BAR_COLORS_MODERN` (:51–60), второй градиент
`--today` (`glass.css:1061–1063`), кремовый `--chip-active-bg` (:32–33, :53–54), `colorErrorBg` на строках
(`MissedCallsWidget.tsx:52, :77`), инлайновый `<style>` с `rgba(255,77,79)` и `rgba(250,140,22)`
(`DashboardPage.tsx:394–397` — удалить из modern-ветки вместе с таблицей остатков, в классике оставить);
hex в `DashboardPage.css:16–21, 279–285` обернуть `html[data-design='classic']` или перевести на
`--c-pos-fg/--c-neg-fg`.

**Блок цветных тегов `glass.css:1267–1374` не удаляется** — он чинит читаемость тегов на всех страницах
тёмного стекла (коммит 7983a4a). Ниже него добавляется `html[data-design='modern'] .ant-tag[data-tone]` с
четырьмя тонами, который его перекрывает. Удаление блока — пункт BACKLOG после миграции семейств.

Элементы на стекле:

- **Теги/пилюли статуса**: `DealStatusTag` получает `data-tone` (positive: CLOSED; negative: CANCELED,
  REJECTED; warning: WAITING_*, PENDING_ADMIN, SHIPMENT_ON_HOLD, REOPENED; neutral: остальные), modern

- **Нейтральные пилюли** (артикул, «30 дней», «Своё»): не пилюли — текст `--c-text-2`; если нужна пилюля —
  `--fill-2`. На одну строку списка не более одной пилюли.
- **Бейджи-счётчики**: нейтральный `--fill-2` + `--c-text-1` («72»); `--c-alert` только для действия.
- **Прогресс-бары**: рельс `--fill-2`, высота 6, радиус 999, трек `--c-accent-fill`; ≥ 100 % → `--c-pos-fg`;
  при `period='day'` отставание дневной цели от доли прошедшего дня → `--c-warn-fg`. Длина бара ≤ 420px.
- **Стековый бар этапов** (зона B): сегменты красятся не тоном, а порядком этапа — `--c-accent-fill` с alpha
  от .9 (NEW) до .35 (IN_DELIVERY) по порядку ключей `statusConfig` в `DealStatusTag.tsx`; warning/negative
  тона — по карте выше; подпись этапа и число — под баром строкой Caption; hover — тултип.
- **Ссылки**: внутри данных — `--c-accent-fg` без подчёркивания; действие секции — класс
  `.ui-section__action`: 13/500 `--c-text-2`, hover `--c-text-1`, Phosphor `CaretRight` 14 после текста.
  Синих ссылок в углах нет.
- **Точки-индикаторы** 7px без свечения: `--c-neg-fg` у блокирующего события и просроченного менеджера,

## 9. Какую страницу доводить до идеала первой

**Дашборд, и только потом Клиенты.**

- Боль — на дашборде: это первый экран после входа и единственная страница, где новое (каркас) и старое
  (контент) стоят рядом в одном окне. Пока он не исправлен, любая следующая страница открывается из
  «старого» дашборда и наследует то же ощущение.
- На дашборде рождается язык, а не паттерн: три уровня материала, шкала шрифта, числа и деньги, семантика
  цвета, пустые состояния, eyebrow-секции. Список клиентов эти правила потребляет, а не задаёт. Делать
  `DataTable` до того, как решено, как выглядят панель, число и статус-пилюля, значит делать его дважды.
- Дашборд даёт 6 из 13 примитивов брифа (`Section`, `Eyebrow`, `StatTile/StatGrid`, `Money`, `EmptyState`,
  `StatusPill`) на одной странице и без риска для 60 табличных страниц: `DataTable`, `Toolbar`,
  `PageHeader`, `DetailLayout`, `FactList`, `DateText` остаются пилоту Клиентов.

Порядок: (0) дашборд по §8 — эталон языка; (1) Клиенты-список — эталон таблиц; (2) карточка клиента —
эталон деталей; далее семейства по брифу §6.

## 10. Definition of Done для дашборда

1. В modern-ветке дашборда нет ни одного `.ant-card`, ни одного инлайнового `fontSize`/`fontWeight`/hex, ни
   одной иконки из `@ant-design/icons` (общие компоненты получают иконку пропом) и ни одного antd `Tag` без
   `data-tone`.
2. Не больше трёх уровней материала (окно → `Section` → строка), одно сплошное пятно (активная пилюля), один
   акцент (число Hero); радиусы 40 → 16 → 10/999; между панелями 24, между зонами 40; `translateY` внутри
   окна отсутствует.
3. Шесть ступеней шрифта §4, `tabular-nums` на всей странице, деньги через `formatMoneyCompact`/`Money`,
   проценты и десятичные с запятой, даты `DD.MM`, «—» только для `null`, ни одного «0 so'm —».
4. Первый экран 1920×1000: приветствие, зона «Сегодня», заголовок «Периода» с баром цели и верх графика
   видны без прокрутки; страница ≤ 1,6 экрана; при нулевом дне ноль сообщается один раз.
5. Роли SUPER_ADMIN, MANAGER, WAREHOUSE, ACCOUNTANT — у каждой свой состав по §6; уровни `NO_STRATEGIC` и
   `NONE` — по таблице §6; все ссылки ведут туда же, куда раньше (URL из `MissedCallsWidget.tsx:51` включая
   `&from=`).
6. Светлая и тёмная тема, 1440, 1920 и 390px; контраст подписей на стекле поверх дефолтного фото ≥ 4.5:1;
   `prefers-reduced-motion` — без анимаций; `prefers-reduced-transparency` — сплошные панели.
7. Классика: открывается, скриншот совпадает со стартовым, тесты зелёные; единственное пересечение с классикой —
   `enabled: SHOW_MY_MONTHLY_GOALS`, названное в теле коммита.
8. Примитивы `Section`, `Eyebrow`, `StatTile/StatGrid`, `Money`, `EmptyState`, `StatusPill` лежат в
   `components/ui/` с `.css` рядом, BEM `ui-*`, без `!important`; `glass.css` стал короче, а не длиннее.
9. `PROGRESS.md` — строка решений по дашборду; `QUESTIONS.md` — не больше 5 новых вопросов, каждый с применённым
   дефолтом; коммиты `feat(ui): rebuild dashboard in the new design` (можно несколько, по шагам §8), тело на
   английском, в конце `New design only.`
