# Промты для Claude Code (Opus 5.5)

Как пользоваться: один раз запустить «Промт 1» (Фаза 0 + пилот, effort **high**), дальше
каждую сессию — «Промт 2» (effort **medium**; **high** для семейства «Аналитика» и файлов
больше 1 500 строк). Между семействами — новая сессия или `/clear`: всю память несут
`docs/design/BRIEF.md`, `PROGRESS.md` и `QUESTIONS.md`, а не история чата.
Раз в несколько сессий открыть `QUESTIONS.md`, поставить галочки и написать «Ответ: …» —
следующая сессия начнёт с них.

---

## Промт 1 — Фаза 0: примитивы и пилот

```
Ты продолжаешь редизайн фронтенда CRM (frontend/: React 19, antd 6, TypeScript, Vite).
Новый дизайн — «матовое стекло» в духе visionOS. Каркас (плавающее меню, шапка, нижняя
панель) и дашборд уже сделаны и являются эталоном. Остальные ~88 страниц надо привести
к нему, одновременно наведя порядок в данных: убрать лишнее из вида, добавить недостающее,
нормализовать форматы — и сделать интерфейс технологичнее и плотнее.

Сначала прочитай полностью docs/design/BRIEF.md и docs/design/PROGRESS.md. Там принципы,
правила про данные (P/S/N), список примитивов, порядок семейств, порядок работы в сессии,
Definition of Done и формат вопросов. Бриф главнее твоих привычек. Вопросов мне перед
началом не задавай: для спорных мест в брифе есть дефолты. Спорное фиксируй в
docs/design/QUESTIONS.md (не больше 5 за сессию, с уже применённым дефолтом).

Задача этой сессии — Фаза 0:

1. Изучи эталон: frontend/src/components/Layout.tsx, ModernHeaderBar.tsx,
   DashboardGreeting.tsx, pages/DashboardPage.tsx, theme/glass.css, theme/tokens.ts.
   Пойми переменные стекла (--win-*, --panel-*, --chip-*, --field-bg) и как включается
   modern (data-design на html + .app-shell).
2. Создай слой примитивов в frontend/src/components/ui/ по §5 брифа: PageHeader, Toolbar,
   StatTile/StatGrid, DataTable, DetailLayout, FactList, Section, StatusPill, Money,
   DateText, EmptyState, Eyebrow. У каждого .tsx и .css рядом, классы с префиксом ui-,
   без inline-стилей и hex; стекло только под html[data-design='modern'], в классике —
   нейтральный вид. Money/DateText/телефоны — через существующие utils/currency.ts,
   utils/phone.ts, lib/name-utils.ts, dayjs. Money уважает скрытие сумм (isMoneyHidden, HIDDEN_MONEY).
   На мобиле (useIsMobile, 768px) DataTable
   отдаёт MobileCardList.
3. Пилот: переведи на примитивы frontend/src/pages/ClientsPage.tsx и ClientDetailPage.tsx,
   применив правила данных §4. Аудит полей (поле · P/S/N · куда ушло / что добавлено)
   покажи таблицей в ответе. Запросы, мутации, гейты ролей, URL-параметры, формы — не менять.
   Презентационные куски ClientDetailPage выноси в components/clients/, поведение не трогай.
4. Проверка: cd frontend && npm run lint && npm run build && npm run test. Классический
   дизайн должен открываться без ошибок. Если доступен браузер — скриншоты 1440 и 390,
   светлая и тёмная тема; проверь контраст текста на стекле в тёмной теме.
5. Коммиты по образцу истории репозитория: заголовок feat(ui): … in the new design,
   тело на английском — что изменилось и почему. Отдельный коммит на примитивы, отдельный
   на пилот. Обнови PROGRESS.md (статусы, строка решений) и QUESTIONS.md.

Закончи в чистом состоянии: сборка зелёная, прогресс записан. В конце ответа: что сделано,
какие решения по данным принял, что ушло в QUESTIONS, какое семейство следующее.
```

## Промт 2 — следующая сессия (одно семейство)

```
Продолжаем редизайн фронтенда CRM. Прочитай docs/design/BRIEF.md, docs/design/PROGRESS.md
и docs/design/QUESTIONS.md; если в QUESTIONS есть мои ответы — сначала примени их.
Возьми первое незакрытое семейство из PROGRESS.md (или: <название семейства>) и пройди
его по §7 брифа: аудит полей P/S/N по каждой странице (таблицей в ответе), перевод на
примитивы из frontend/src/components/ui/ (расширять пропсами, не копировать паттерны в
страницы), правила данных §4, Definition of Done §10.

Логику страниц не менять. Вопросов не задавай — дефолты из брифа, спорное в QUESTIONS.md
(≤5, с применённым дефолтом). Проверка: cd frontend && npm run lint && npm run build &&
npm run test; классика открывается. Коммит на 2–4 страницы в стиле истории репозитория.
Закончи с зелёной сборкой и обновлённым PROGRESS.md; семейство наполовину не оставляй —
лучше меньше страниц, но до конца.
```

## Промт 3 — если нужно «подчистить» одну страницу

```
Прочитай docs/design/BRIEF.md. Приведи frontend/src/pages/<Файл>.tsx к Definition of Done
§10: аудит полей P/S/N таблицей в ответе, примитивы из components/ui, правила данных §4,
без inline-стилей и hex, светлая/тёмная, 1440/390. Логику не менять. Проверка lint/build/
test, коммит в стиле истории, строка в PROGRESS.md.
```

## Что сказать Claude, если он спрашивает лишнее

- «Убирать ли поле X?» → «По брифу §4.2: сомнение — не убирать, записать в QUESTIONS, идти дальше.»
- «Трогать ли бэкенд?» → «Нет, кроме исключения §4.3. В BACKLOG.»
- «Улучшать ли классику?» → «Нет, только не ломать. §3 п. 10.»
- «Добавить библиотеку?» → «Только через QUESTIONS.»
